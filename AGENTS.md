- Gotcha Treasury, phase 1 (Oct 16, drizzle 0022, super admin → Admin → Treasury, `src/components/admin/TreasuryPanel.tsx`, `src/lib/treasury.functions.ts`): deploys `GotchaFeeSplitter` (source `src/contracts/GotchaFeeSplitter.sol`, ABI `GotchaFeeSplitter.abi.json`, constants `src/contracts/splitter.ts`). Compiled in the browser by a classic Web Worker `public/solc/solc-worker.js` that loads the self-hosted official solc-js `public/solc/soljson-v0.8.24+commit.e11b9ed9.js` (from the `solc@0.8.24` npm package) and calls `solidity_compile` directly; settings optimizer 200 runs, evmVersion shanghai, file name `GotchaFeeSplitter.sol` (changing the source, file name or settings changes the bytecode: regenerate `EXPECTED_BYTECODE_SHA256` = SHA-256 of the creation bytecode hex text). Deploy is blocked unless the browser's bytecode matches that fingerprint; deploys from the injected wallet (switches/adds ApeChain 33139 or Curtis 33111, Curtis default). `adminRecordSplitter` checks the receipt, that the tx input minus the 10 constructor-arg words hashes to the fingerprint, and reads owner/keeper/getBuckets from the contract before saving `treasury_splitters` (one `is_active` per chain). The page shows ApeScan verification settings, constructor args, Copy source / standard JSON input. Fee routing plan (later phase): Refill payments call `deposit()` with the purchase ID appended (the splitter has `receive()` but no `fallback()`, so a plain transfer WITH data would revert); tested on a local chain.
- Gotcha Treasury, phases 2–3 (Oct 16, drizzle 0023; Admin → Treasury tabs Dashboard / Keeper bot / Settings / Deploy, `TreasuryDashboard.tsx`): settings in `app_config.treasury` (`src/lib/treasury-settings.ts`, defaults: DRY RUN ON, kill switch off, buffer 5%, slippage 3%, re-post targets on >2% move, every buy bucket disabled). Keeper (`src/lib/treasury-keeper.server.ts`, chain/market helpers `treasury-market.server.ts`) runs from pg_cron every 10 min → `POST /api/treasury-keeper` (no secret: `treasury_try_lock` keeps runs ≥8 min apart and never overlapping) and from "Run keeper now". Each run: payoutAll; floors from OpenSea best listings (native-ETH only) → Relay `/quote/v2` EXACT_OUTPUT (origin ApeChain 33139 native) → target ×(1+buffer), buckets 4 and 5 always equal; open jobs advance; ready enabled buckets start jobs only when priced (target ≠ 0, except stock buckets 2/3 which just release to their recipient), preflight settings are complete, and no failed job still holds released funds (admin Retry = continue from `last_ok_status`, or Close). Job states releasing → released → bridging (Relay EXACT_INPUT, request id saved before sending) → bridged → buying (OpenSea `fulfillment_data`, input_data encoded by component name with the Seaport 1.6 ABI in treasury-market; price ≤ max spend and price+gas ≤ ETH held, else hold) → bought → delivering (safeTransferFrom to the prize wallet) → delivered; burn bucket 5 = Relay APE → $STONKBROKER with recipient 0x…dEaD. On Curtis (testnet) jobs end after the release. Secrets: KEEPER_PRIVATE_KEY (keeper = buyer wallet), OPENSEA_API_KEY, optional RELAY_API_KEY, TELEGRAM_BOT_TOKEN (+ chat ID setting), ETH_RPC_URL, ROBINHOOD_RPC_URL (rpc.server now maps chain 1 → ETH_RPC_URL). Manual dashboard buttons (payoutAll / syncSurplus / release) send from the keeper wallet even in dry run, blocked by the kill switch. Gotcha spin payments go to the active ApeChain mainnet splitter when `fees_to_splitter` is on (`feeRecipient`; `splitterPaymentData` = deposit() selector + purchase id; `checkPayment` accepts both forms). Tested end to end on two local chains with mocked OpenSea/Relay (24 checks) — not against the real APIs.
