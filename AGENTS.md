- Shared page artwork is mounted once from the root shell through `PageArtwork`; this keeps every application page visually consistent.
- Grant deletion uses a stationary pointer-capture surface and motion values for the moving row; this avoids touch coordinate drift and per-frame React renders while preserving vertical scrolling.
- Resolve viem's optional isows transport to the runtime-native WebSocket; importing Node ws can break server module loading even when draws use HTTP.
- Empty-spin guidance is injected into `GotchaMachine` as an optional callback so reusable machine logic stays independent of page-specific refill controls.
- USD-priced native-APE checkout fetches Coinbase spot rates server-side and locks the exact wei amount in a purchase before wallet approval; never trust client conversion or silently fall back to a fixed rate.
- Purchase settings reach players through a narrow authenticated server function; do not broaden configuration-table read policies for checkout.

- Player guide chat: streaming endpoint at src/routes/api/guide-chat.ts (server route, bearer-authed), handler in src/lib/guide-chat.server.ts (Claude via Lovable AI Gateway /v1/messages), one conversation per user persisted in guide_messages; UI at src/routes/_authenticated/guide.tsx using AI Elements + useChat.
- App-wide font is set once in src/styles.css with a universal !important rule — component-level font choices are intentionally overridden.
- Sign-in and Refill windows are app-wide: open them with `openSignIn()` / `openRefill()` from `src/components/wallet/walletUi.ts`; `WalletHost` (root shell) renders them inside one lazily loaded PrivyProvider (`PrivyLayer`).
- Sign-in is Login with Glyph only, through the app's own branded window (`SignInWindow`, dark panel + #f6c343 gold), never Privy's login modal: its button calls `useGlyphAccount().login()` (`src/components/wallet/glyph.ts`: Privy `loginWithCrossAppAccount` to Glyph's app `cly38x0w10ac945q9yg9sm71i`) straight from the tap (popup blockers), and the same window shows loading states and, if Privy doesn't start within 12s, the exact origin to add under Privy → App settings → Domains. `PrivyLayer` uses plain `PrivyProvider` — do NOT use the Glyph SDK's `GlyphPrivyProvider`/`useGlyph`: it renders nothing (including the Refill/Burn windows inside it) until a fetch to useglyph.io succeeds and never retries. The Glyph wallet is the `cross_app` linked account whose `providerApp.id` is Glyph's (`embeddedWallets[0].address`); transactions go through `useCrossAppAccounts().sendTransaction(tx, { address })`. The app's Privy App ID is `purchase.privy_app_id`. `privySignIn` / `linkPrivyAccount` verify the Privy access token (JWKS) + read linked accounts with `PRIVY_APP_SECRET`; the Glyph wallet arrives as a `cross_app` linked account and is stored as `wallets.kind = 'glyph'` (preferred default). Payments and burns sign with `useGlyphAccount().sendTransaction`. Supabase stays the session of record; there is no email sign-in fallback.
- Guide event knowledge (ApeFest 2026, Charleston; official ApeGames account @goApeGames on X, stored as `event_info.games_handle`): `src/lib/event-knowledge.server.ts` uses Firecrawl (`FIRECRAWL_API_KEY`) to scrape/search boredapeyachtclub.com only, caches pages in `event_knowledge` (refresh every `event_info.refresh_hours`), and the guide also gets a `search_apefest_info` tool. Scraped text is quoted as untrusted reference data in the system prompt.
- Admin spin grants come in two kinds (`spin_credits.kind` / `spin_grants.kind`): `real` = paid-equivalent on-chain spin, `demo` = practice spin on the demo machine (no prizes/points, redeemed via `use_demo_spins`, no 30-minute wait). Granted spins are usable immediately, spent before purchased ones and exempt from per-player spin limits; the admin Grants tab lists every grant with usage. Count only `kind = 'real'` credits as drawable spins.
- Database migrations go in `drizzle/migrations/NNNN_name.sql` with an entry in `drizzle/migrations/meta/_journal.json` (increasing `when`); Lovable applies them on sync with `drizzle-kit migrate`. Write them idempotent (`if not exists`, `create or replace`, `on conflict do nothing`). `supabase/migrations` is the older history and is not applied automatically. Storage steps (`storage.buckets` / policies on `storage.objects`) are each wrapped in `do $outer$ … exception when others … $outer$` so a permission error there can't stop the rest of a migration; evidence (Oct 11) suggests the live database hadn't received drizzle 0009, so check that migrations actually apply.
- On-chain draw setup: Admin → Chainlink VRF → "Set up" (`src/lib/vrf-setup.server.ts`) creates and funds a VRF v2.5 subscription in native ETH, deploys GotchaVRF from `src/lib/gotchaVrfBytecode.server.ts` (regenerate after changing the contract), and adds it as consumer, using `VRF_OPERATOR_PRIVATE_KEY`; each step is saved to `app_config.vrf` so reruns resume. Real spins and purchases are switched on with `adminVrfSwitch` / `adminPurchaseSwitch`, which check readiness first. Players learn whether the draw is open via `getDrawStatus` (they can't read `app_config.vrf`).
- Signed-in demo spins (granted + the free one every 30 minutes, timed by the server) are drawn server-side and stored in `demo_spins`; `get_leaderboard` returns the demo board or the live board (real spins + admin adjustments) per `app_config.leaderboard.mode`. Signed-out visitors' demo spins stay in the browser.
- Wallet transactions (Refill payments, NFT burns) share `usePrivyWalletAdapter` / `useInjectedWalletAdapter`; long confirm loops must reset their cancel flag on mount (React dev mounts twice).
- Spin music (`music.ts`): the game uses `createJukebox(0.7, "rendered")`: a plain `<audio>` player (plays on every iPhone setting, like the reveal sounds) with the loudness baked into the audio: tracks are decoded once (OfflineAudioContext, decode only), `renderWav(buffer, level)` writes a WAV at the slider level, and a slider move re-renders and swaps it in at the same position (debounced 150 ms; 0 = muted). Why: on the owner's iPhone the sound-engine routes ("engine", "engine-unlocked") go silent intermittently (18:36, 21:18) while plain players always play, and iPhones ignore `audio.volume`. Keep music on a plain player. Other routes stay for `/sound-test`. Reveal pop/fanfare (`createSfx`) are WAV blobs on plain `<audio>` players unlocked in the tap (`sfx.prime()`).
- Never call Glyph/Privy cross-app login (`useGlyphAccount().login()`) while one of our Radix dialogs is open: Privy drives the Glyph tab from its own "Connecting to Glyph" modal, and a second modal's focus trap makes Privy cancel ("User canceled flow"), leaving the tab on about:blank. `GlyphBridge` unmounts `SignInWindow` (handedOff) before calling login and reopens it on failure; Refill/Burn "connect" hands over via `requestLinkWallet({ then: "refill" })`.
- There is exactly one sign-in window: `WalletHost` renders `HostedSignInWindow` (always first in its fragment, so it never remounts); `GlyphBridge` feeds it through `setSignInControls` instead of rendering its own (swapping windows made it flash). Privy builds Glyph's auth link with `redirect_to: window.location.href`, so every live domain (apex and www) must be in the Privy app's allowed domains or the Glyph tab stays on about:blank.
- Glyph's sign-in tab returns to the site with `?privy_oauth_code&privy_oauth_state`; Privy only hands that back to the game tab (and closes the Glyph tab) when PrivyProvider starts on that page, so `WalletHost` detects those params on mount, activates the wallet layer immediately and shows `GlyphReturnScreen` instead of the site. Otherwise it preloads `PrivyLayer` + Privy config when the page is idle. `GlyphBridge` logs out of Privy only on a real app sign-out (user → none), never just because a tab has no player (Privy's session is shared across tabs).
- Back arrow: `SiteHeader`'s `BackButton` shows on every page except `/`; it uses `router.history.back()` when `canGoBack()`, otherwise navigates home.
- Contact email is `CONTACT_EMAIL` (`src/lib/contact-email.ts`, fun@ApeGamesGotcha.com): team emails go to `app_config.contact.notify_to` (set to it by drizzle 0007) or to it when unset.
- NFTs: the collection is `APEGAMES_NFT_CONTRACT` 0x8Bb7b20291A9fA2F25705b8487194B410808c28b (ERC721Enumerable on ApeChain, on-chain `levelOf`). `syncNfts` reads every wallet on the account in parallel (one failing wallet doesn't stop the rest), takes levels from `levelOf` (metadata fallback), and releases holdings no longer in any wallet; the dashboard runs it automatically on load and whenever the wallet list changes.
- Wallets: at most `MAX_WALLETS` (5) per player, enforced in `linkWallet` and `syncPrivyWallets`. Add wallet opens the sign-in window in link mode with two choices: link Glyph, or "Connect another wallet" (Privy `useConnectWallet` → WalletConnect/MetaMask/Coinbase/Rainbow; our window steps aside first), then the wallet signs our nonce and `linkWallet` verifies it (EOA or ERC-1271/6492 on ApeChain). Do NOT set `loginMethodsAndOrder` on PrivyProvider: Privy then builds the connect-wallet list from it and the picker shows "No wallets found"; the list is `appearance.walletList` (`EXTERNAL_WALLETS`).
- Prize pool (`src/lib/prize-pool.ts`): limited-stock active prizes; `prizes.stocked` (drizzle 0008) is each prize's stock as last set by an admin (any saved change to the stock in `adminUpsertPrize`, up or down, resets it; draws don't). There is no overall prize cap: each stock is a Postgres int (≤ 2,147,483,647), the contract takes up to 32 prizes with uint32 stock. Players: only at 0% left (`onHold`) do `startDraw` / `createSpinPurchase` refuse with `RESTOCK_MESSAGE`, `getDrawStatus.restocking` / `getPurchaseSettings.on_hold` pause the machine and Refill, and `RestockPopup` (public `getPrizePoolStatus`, onHold only) shows once per hold per session. Admins only: `lowStock` at ≤20% (`adminPoolStatus`) shows a warning on every admin tab. Demo spins are unaffected.
- Prize reveal in the machine window has no card/square frame (round glow); a prize's uploaded photo (`image_url`) shows round via `PrizeImage` (`src/components/PrizeImage.tsx`).
- About page: `src/routes/about.tsx` (menu → About).
- Roles: every admin has `user_roles.role = 'admin'`; exactly ONE is the super admin. `src/lib/roles.server.ts` (`superAdminId` / `roleOf`) decides it: the `super_admins` table (drizzle 0009) when it exists and has a row; otherwise the account with `app_metadata.super_admin = true`, else the admin who first promoted someone (audit `role.promoted`), else the earliest-created admin, which then gets marked. Never treat "every admin" as super (that made a promoted admin show as a second, undeletable super admin on Oct 11). Promoted admins get Setup checklist, Prizes & odds, Grants & levels, Leaderboard & prizes; the super admin also gets Configuration, Chainlink VRF, Admins (`superListAccounts` / `superSetRole` / `superUpdateAccount` / `superDeleteAccount` in `src/lib/users.functions.ts`) and the Audit log. Super-only server functions call `assertSuperAdmin` / `assertSuper`; the super admin can't be demoted or deleted from the app. `useAuth().isSuperAdmin` comes from the server (`getMyRole`).
- My account (`/account`): each player edits only their own username (`usernameSchema`, unique case-insensitive) and profile picture (private `avatars` bucket, own folder `<uid>/…`). These work even if drizzle 0009 never reached the live database (Oct 11: live DB had no `profiles.updated_at` and no `avatars` bucket): `updateMyProfile` writes only `display_name` (then stamps `updated_at` if it exists); uploads use `getAvatarUploadUrl` (creates the bucket if missing, returns a one-time signed upload link) + `uploadToSignedUrl`; the picture path is saved in the user's `app_metadata.avatar_path` and in `profiles.avatar_url` when that column exists; `Avatar` gets signed links from `getAvatarUrls` (own, or any for the super admin). Profile rows change only through server functions.
- Sign-out is `signOutEverywhere()` (`src/lib/sign-out.ts`): Privy/Glyph logout (registered by `GlyphBridge` via `registerPrivyLogout`, loading the layer if needed), removal of all `privy*` storage/cookies and pending-payment keys, Supabase `signOut({ scope: "global" })`, then a full reload to `/`. The sign-in window never offers "Continue as…": a leftover Privy session is logged out before the Glyph button is enabled, so every sign-in goes through Glyph.
- Security (drizzle 0010): default usernames are `Ape-XXXXXX` (never email prefixes or Privy IDs); `get_leaderboard` returns `user_id` only for the caller's own row (rows keyed by position); guide chat rows are written only by the server (`supabaseAdmin`), with input caps in `guide-chat.server.ts`; avatars readable only by owner/admins; anon has no write grants on app tables.
- Sign-in proves wallet ownership in two taps: Glyph "Approve" (Privy cross-app login), then the Glyph wallet signs a one-time SIWE-style message (`getWalletSignInChallenge` → `useGlyphAccount().signMessage`). The message is sealed with an HMAC (`SIGNIN_PROOF_SECRET`, falling back to the service-role key), valid 10 minutes, and checked by `verifyWalletProof` (`src/lib/wallet-proof.server.ts`; local check, then ERC-1271/6492 on ApeChain). `privySignIn` / `linkPrivyAccount` refuse without a valid `proof`.
- Music volume: `getMusicVolume` / `setMusicVolume` / `onMusicVolume` in `sound.ts` (localStorage `gm-music-volume-v2`, default 1 = the original loudness; linear). `TreeVolume` is the vertical slider on the left palm trunk (no marks drawn): top = loudest (lined up with the plate's Chainlink pill), bottom = off (lined up with the One spin / Spin all row); it measures those elements, so keep their class names.
- DEMO / LIVE buttons: `SpinArcade` (home + dashboard) holds the picked mode (null on every page load, both buttons blink, Click To Spin greyed). DEMO → `DemoGotchaMachine` demo spins; LIVE → real spins (signed out: green Click To Spin opens sign-in). Out of spins, Click To Spin keeps glowing and `useRefillGuide` scrolls to and pulses the Refill button. Mode buttons lock while a spin is in progress.
- IRL claim step: in a live draw, a revealed prize with `prizes.is_physical` shows "Claim your IRL prize" under the status plate (`revealAction`), and when the session ends the claim dialog (`ClaimForm` from `IrlPrizes.tsx`) opens for any unclaimed one; "Later" leaves it in Your IRL prizes on My Machine.
- Server builds get an inert `@privy-io/react-auth` (`src/lib/privy-server-stub.ts`, plugin `privy-browser-only` in `vite.config.ts`). With the real package, nitro put viem's core inside Privy's server chunk, so live draws loaded Privy's Node-only pino/sonic-boom logger, which fails in the worker with `The "superCtor.prototype" property must be of type object` (`require("node:events")` isn't a class there). Keep Privy browser-only; never import it from server code.
- Personal data (drizzle 0011): through the database API players read only their own `prize_claims`, `profiles`, `wallets`, `privy_accounts`; `contact_messages` has no client access; avatars are readable by the owner and the super admin. Admin screens read these only through server functions that check the role.
- Chain RPCs (`src/lib/rpc.server.ts`): every server viem client uses `resilientTransport` + `chainDef` — private RPC secret first (`VRF_RPC_URL` for Base, `APECHAIN_RPC_URL` for ApeChain), then the admin-configured `rpc_url`, then public RPCs; JSON-RPC batching, Multicall3 reads, retries with back-off on 429/5xx. Public Base RPC (mainnet.base.org) rate-limits with 429. Show players `chainErrorMessage(e)`, never raw viem errors. `checkDraw` treats a busy chain as "still drawing"; live machine polls every 3s.
- The AI guide is signed-in only (paid service): `/api/guide-chat` returns 401 without a session and limits each player (20 questions / 10 min, 150 / day, counted in `guide_messages`); signed-out visitors see a "Sign in to chat" card (closes the sheet before `openSignIn()`) and the Contact form.
- Prize pictures (drizzle 0014): the `prize-images` bucket is public on purpose (owner's decision: prize photos aren't sensitive); `PrizeImage` / `usePrizeImageUrl` use `getPublicUrl`. Only admins upload/replace/delete. If a security scan flags "anyone can download files in prize-images", mark it as not a risk; don't lock it down again.
- External wallets (Add wallet → Connect another wallet): Privy's picker can close before a phone wallet app answers; `connectStarted` keeps a late `onSuccess` valid for 3 minutes and the "picker closed" fallback waits while the page is hidden.
- Framed pages (e.g. the Lovable editor preview, `window.top !== window.self`): Glyph's sign-in tab can't report back to a framed page (iPhone Safari partitions framed storage), so it stayed on about:blank. The sign-in window there shows "Open sign-in in a new tab", which opens the same URL with `?signin=1` (or `=refill`); `WalletHost` strips the param and opens the sign-in window in that top-level tab.
- Admin "Grant spins / adjust points" finds the player by username (exact, case-insensitive), email, or linked wallet address (`findPlayer` in `app.functions.ts`; `adminGrant` takes `who`, `email` still accepted). Two players with the same name → asks for the email.
- Usernames are unique, ignoring capitals and surrounding spaces (drizzle 0015: unique index on `lower(btrim(display_name))`; older duplicates renamed `Ape-XXXXXXXX`, earliest account keeps the name; `handle_new_user` picks an unused default). The server checks first (`assertUsernameFree`) and maps the database's 23505 to `USERNAME_TAKEN`; My account checks live while typing (`checkUsername`) and shows the error under the field.
- Prizes & odds lists prizes legendary → epic → rare → common; within a rarity the highest dollar value in the name ("$50") first, then points, then name (`sortPrizes` in `src/lib/prize-order.ts`; admin applies it on load/save, not while typing). The machine's Prize pool card uses the same order.
- Admin console actions that change anything ask first: `confirmAction({ title, description, confirmLabel, destructive })` from `src/components/ConfirmAction.tsx` (one `ConfirmHost` mounted in the admin page; resolves true only on confirm). Use it for every new admin action. After a successful grant the Grant form clears (player, spins, points, note) so it can't be sent twice by accident; the level override clears too.
- Admin → IRL claims tab (every admin; `IrlClaimsPanel` in admin.tsx): tiles To ship / Pick up at ApeFest / Won, not claimed yet / Delivered-closed, each claim card shows prize, username + email, recipient, phone, shipping address (Copy shipping label), winner's note, and status / tracking / note to winner (saved with `adminUpdateClaim` after a confirm). `adminListIrlClaims` returns `username` from profiles. It replaced the claims card on Leaderboard & prizes.
- Admin tabs use the LIVE button green (`.admin-tabs` in src/styles.css, same gradient/shadow as `.gm-pick-live`); the picked tab is pressed in with a glow and a light border.
